# GreyKnight - the guide

> Leader = `Space` throughout: `<leader>ff` means `Space`, then `f`, then `f`. Every key on one page:
> [CHEATSHEET](../CHEATSHEET.md). In Neovim `<leader>gd` opens these read-only; `gd` or `Enter` on a link follows it,
> `Ctrl+o` goes back.

| Topic | What is in it |
|-------|---------------|
| [Getting started](start.md) | The first launch, the start screen, the modes, which-key, tips - and when something goes wrong (the error log) |

| [Files](files.md) | The file tree: searches (by regex too), moving, copying, renaming, script slots; oil; harpoon; bookmarks |
| [Windows, buffers, terminals, sessions](windows.md) | Splits, moving between them, resizing; buffers and the recent ones; terminal windows; sessions per project |
| [Finding](find.md) | Pickers for files, words, symbols; search and replace across the project; flash jumps |
| [Code](code.md) | Editing, surround, the language servers, completion, diagnostics and Trouble, formatting, markdown, hex - and Java / Angular |
| [Running and debugging](run-debug.md) | Scripts as tasks in a real terminal, the REPL, errors marked in the code; debugging Python and bash |
| [Git](git.md) | Lazygit, reviews with codediff (VS Code's diff), gitsigns in the files |
| [Remote](ssh.md) | Over SSH from PuTTY or Windows Terminal, the clipboard, the project dashboard's Dev Environment |
| [Testbook](testbook.md) | Workflows to try by hand - the agent's edits reviewed, debugging, renaming, git, speech to text - what to do, what you should see |
| [G3 development](../G3-DEVELOPMENT.md) | Java (jdtls, TestNG, debugging), ngx-his (Angular), html5 clients (AngularJS) - with or without IntelliJ |
